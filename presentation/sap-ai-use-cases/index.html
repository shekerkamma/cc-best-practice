📦 Supply Chain
Implementation Guide
1
Start read-only
Focus on informational queries first (stock levels, order lists). Compare bot output to standard SAP reports like MB52 to validate accuracy before expanding scope.
2
Create HANA views
Build an InventoryStatus view joining stock, open POs, and in-transit data. Let the bot query this simple view rather than composing complex joins — reduces error chance significantly.
3
Enable chart output
Configure the chart.js step in Power Automate. Bar charts of stock by warehouse or trend lines of stock over time are highly valued by supply chain managers.
4
Add proactive alerts
Schedule Power Automate to run daily checks for parts below safety stock and post Teams alerts. Turns Q&A into a proactive shortage-prevention assistant.
5
Define schema in prompt
Include field definitions: material, plant, vendor, quantity fields, and join keys. Incomplete schema = wrong SQL. Test with varied phrasings before go-live.

📈 Sales
Implementation Guide
1
Pre-define common queries
Include 6-week trend and top-5-products examples in the system prompt as few-shot examples. This anchors the LLM to produce correct SQL for typical sales requests.
2
Inject date intelligence
Power Automate can detect phrases like 'last quarter' and insert actual date ranges before passing to the LLM. Maintain a calendar table with fiscal quarter definitions.
3
Maintain summary tables
Pre-aggregate sales by week/product/region. Let the bot query these instead of raw line-item tables. Enables sub-second responses even for large datasets.
4
Enable chart rendering
Configure the chart.js connector in the Power Automate flow. For trend queries, a line chart in Teams is far more impactful than a table of numbers.
5
Test multi-turn context
Verify conversation history is passed in the OpenAI payload. Users often ask 'which week was highest?' after a trend query — the bot must remember Product Z without prompting.

🔍 Data Governance
Implementation Guide
1
Pre-define check queries
Build a library of SQL queries for known data quality rules. The LLM selects the right one based on user intent. This trades some flexibility for reliability — wrong SQL means wrong audit results.
2
Count-first pattern
Run COUNT(*) first. If ≤ 20 records, list inline. If > 20, summarise and offer export to SharePoint/Excel via Power Automate. Keeps chat readable and manageable.
3
Schedule weekly digest
Post an automated weekly Data Quality report to a governance Teams channel: '8 products missing owner · 3 customers missing region'. Users ask follow-ups inline.
4
Add corrective actions
Extend the bot to fix issues: after listing products missing owner, user says 'Assign John Doe to MAT-4892' and the bot calls OData PATCH. Log all updates for audit trail.
5
Segment by domain
If the bot covers multiple modules, split context by domain (sales vs HR data quality). Either use separate bots per team, or train the AI to clarify context when queries are ambiguous.

⚙️ Operations
Implementation Guide
1
Index docs in Azure Search
Upload equipment manuals and troubleshooting guides as PDFs. Build an Azure Cognitive Search index and embed a retrieval step in the Power Automate flow before the OpenAI call.
2
Build an intent router
Before querying HANA or docs, classify the user's intent: analytics query → SQL path; operational problem → doc search path. Power Virtual Agents topics or a classifier prompt handles routing.
3
Dialog flow for PM orders
If the bot offers to create a PM order, it must collect Equipment ID, problem description, and priority. Design a multi-turn dialog, then confirm before calling BAPI_ALM_ORDER_CREATE.
4
Test in QA sandbox first
Validate the full cycle: operator asks question → correct doc snippet returned → 'cannot fix' path triggered → PM order appears correctly in SAP QA. Check all required fields are populated.
5
Consider voice / mobile
Operators on the shop floor benefit from hands-free access. Teams mobile or a tablet works today. Keep bot responses short and scannable — they may be displayed on small screens or spoken via TTS.

💰 Finance
Implementation Guide
1
Map accounts in prompt
Include account mappings in the system prompt: 'Revenue = accounts 400000–499999; COGS = 500000–549999'. Without this, the LLM cannot translate terms like 'gross margin' into correct GL queries.
2
Validate against period close
Before go-live, run the bot against the last closed period and compare with verified financial statements. Any discrepancy must be resolved — financial data has zero tolerance for inaccuracy.
3
Handle currency consolidation
Multi-entity groups need currency translation. Either pre-convert to group currency in a reporting view, or handle FX explicitly in SQL. Document clearly so the AI knows what currency amounts represent.
4
Role-based access tiers
CFO sees all entities; division heads see their P&L only; regional managers see their region. Map restrictions to SAP auth objects or add WHERE clauses per user in the Azure Function layer.
5
Integrate plan data
If budget/plan is in SAP BPC or IBP, expose it via OData or a replicated HANA table. The bot can then answer budget-vs-actual questions — one of the most requested finance analytics use cases.

👥 HR
Implementation Guide
1
Apply strict GDPR controls
Enforce that queries always filter by the requesting manager's org unit. Never return individual personal data without authorisation. Consider aggregate-only responses for sensitive attributes like salary or medical data.
2
Build org-aware SQL logic
The Azure Function should automatically append WHERE OrgUnit IN (user's authorised units) based on the logged-in user's profile. This prevents accidental over-disclosure even if the LLM generates a broad query.
3
Integrate training systems
If mandatory training is tracked in a standalone LMS outside SAP, replicate completion data into HANA or expose it via API. A unified view avoids partial results when checking compliance.
4
Add automated nudges
After listing overdue employees, offer to send reminders automatically via Power Automate (Teams message or email). This closes the loop from insight to action — a key differentiator over static HR reports.
5
Privacy review before launch
Have legal/DPO review the data fields the bot can access. Document which queries are permitted, which require aggregation, and which are blocked outright. Include these rules in the system prompt as hard constraints.
